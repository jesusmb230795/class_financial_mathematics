# Reproducible Computational Finance Stack

Module: Setup and Python Ecosystem

## Lesson summary

Computational finance work is only useful when results can be reproduced by the instructor, students, and automated build systems. This note defines the technical contract for the course environment: Python version management, dependency locking, notebook execution, secrets handling, and book validation.

The course uses `pyenv` for the local Python interpreter, `uv` for dependency resolution and virtual environment management, JupyterLab for interactive work, and Jupyter Book for the published textbook.

## Learning objectives

By the end of this lesson, students should be able to:

- explain why reproducibility matters in quantitative financial mathematics;
- distinguish interpreter management from dependency management;
- install and synchronize the project environment with `pyenv` and `uv`;
- launch JupyterLab from the project environment;
- understand why notebook execution is disabled during the default book build;
- handle API credentials without committing secrets;
- run the validation commands required before sharing work.

## Environment contract

| Component | Course decision | Purpose |
| --- | --- | --- |
| Python | Python 3.12 or newer, pinned locally with `.python-version` | Keeps the interpreter consistent across machines |
| Dependencies | `pyproject.toml` plus `uv.lock` | Locks the scientific Python stack deterministically |
| Virtual environment | `.venv/`, created by `uv sync` | Isolates course packages from system Python |
| Interactive work | `uv run jupyter lab` | Ensures notebooks use the project environment |
| Book build | `uv run jupyter-book build .` or `make book` | Generates the static HTML textbook |
| Execution policy | `execute_notebooks: "off"` | Avoids build failures from external APIs and long-running simulations |
| Secrets | local `.env` or exported shell variables | Keeps API keys out of Git history |

## Repository structure

| Path | Role |
| --- | --- |
| `_config.yml` | Jupyter Book configuration, execution policy, theme behavior, and ignored draft files |
| `_toc.yml` | Book navigation and module structure |
| `chapters/` | Module overview pages, project pages, and deep research drafts |
| `chapters/DR_*.md` | Deep research source files excluded from the build until integrated |
| `notebooks/class/` | Class notebooks and executable MyST notes |
| `src/` | Reusable Python functions that should not be duplicated across notebooks |
| `img/` | Reusable visual assets |
| `material/` | Original readings and supporting PDFs |
| `.env.example` | Safe template for local data API credentials |
| `pyproject.toml` | Project metadata and dependency declarations |
| `uv.lock` | Locked dependency graph generated by `uv` |

## Local workflow

The base setup is:

```bash
pyenv install 3.12.12
pyenv local 3.12.12
uv sync
```

Launch notebooks from the project environment:

```bash
uv run jupyter lab
```

Build the book:

```bash
make book
```

Run a minimal environment check:

```bash
uv run python --version
uv run python -c "import pandas, numpy, scipy, statsmodels, sklearn, plotly, ipywidgets; print('environment ok')"
```

## Notebook execution policy

The default Jupyter Book build does not execute notebooks:

```yaml
execute:
  execute_notebooks: "off"
```

This is intentional. Several finance notebooks depend on external data providers such as Yahoo Finance, FRED, and Banxico. Those sources can fail because of network availability, API credentials, rate limits, or provider-side changes.

For teaching, students should run notebooks interactively in JupyterLab. For publication, selected notebooks can later be executed and reviewed manually, or the project can introduce a controlled CI build with secrets and cache settings.

## Data credentials

Some future notebooks may require API credentials:

| Provider | Example variable | Use |
| --- | --- | --- |
| Banxico SIE | `BANXICO_TOKEN` | Mexican macroeconomic and interest-rate series |
| FRED | `FRED_API_KEY` | US macroeconomic and Treasury series |

Create a local `.env` from the tracked template when needed:

```bash
cp .env.example .env
```

Never commit real tokens. The `.env` file is ignored by Git.

## Interactive outputs

Interactive charts should be designed with two environments in mind:

- In JupyterLab, `ipywidgets` and Plotly can provide sliders, linked controls, and exploratory dashboards.
- In the static Jupyter Book, interactive output must be verified after build. If an output is fragile, include a static fallback figure or a clear instruction to run the notebook in JupyterLab.

For Plotly-heavy notebooks, set the renderer explicitly when needed:

```python
import plotly.io as pio

pio.renderers.default = "notebook_connected"
```

Renderer settings should be tested in the built book before relying on them for final publication.

## Notebook version-control hygiene

Notebook files can create noisy Git diffs because they contain execution counts, metadata, and outputs. The course should keep source changes reviewable:

- avoid committing API keys, credentials, or printed secrets;
- clear large outputs before committing notebooks;
- move reusable code into `src/`;
- keep generated HTML under `_build/`, which is ignored by Git;
- prefer MyST Markdown notes when a lesson is mostly narrative plus small code examples.

A future hardening step is to add `pre-commit` and `nbstripout` so notebook output stripping is enforced automatically before commits.

## Validation checklist

Before sharing changes, run:

```bash
git diff --check
make book
```

For environment-sensitive changes, also run:

```bash
uv run python --version
uv run python -c "import pandas, numpy, scipy, statsmodels, sklearn; print('core imports ok')"
```
